How it works

A narrow rule, checked before it reaches you

  1. 1 · A flaw goes public

    We write a rule for exactly that plugin and version

    Not a broad filter that might break your shop. The rule is tested against the exploit and against normal traffic, and a person reviews it.

  2. 2 · The rule is signed

    Your site checks it before installing

    Guardian verifies the signature, the expiry date and the version number. A fake, stale or replayed update is refused.

  3. 3 · Attacks are blocked

    Everything else passes

    Only requests that match the rule get a 403. If anything goes wrong inside Guardian, your site keeps working.

Open source

A security plugin you do not have to take on trust

The engine that runs on your server is open source, so you, your agency or an auditor can read exactly what it does.

Rules are data, never code

A rule is a small JSON description of a request. It cannot run anything on your server, which also keeps it within WordPress.org's rules.

Signed, expiring, no rollbacks

Updates carry an Ed25519 signature and an expiry. An older version cannot replace a newer one.

Fails open

An error inside Guardian lets the request through and logs it. A time budget stops slow rules from slowing your pages.

A way out

Add one line, define( 'GUARDIAN_SAFE_MODE', true );, or create a file named guardian-disable, and Guardian switches off without touching the database.

Your data stays home

The free engine sends nothing about your site. Paid plans share only what they need, such as plugin versions and event counts, with truncated IP addresses.

Tested in the open

135 unit tests and an end-to-end suite against a real WordPress site cover blocking, normal traffic, version scoping, the off switch and uninstall.

Questions

Straight answers

Is it ready to use?

No. The engine is built and tested, and the rule service is still to come. Join the waitlist and we will tell you when early access opens. We will not claim more than we have shipped.

How is it different from Wordfence and similar plugins?

They are good products. We are aiming at speed and simplicity. For example, Wordfence says free users get new firewall rules 30 days after paying users. We plan 7 days for the free plan, and paid users get rules immediately. The code is open, and the plugin does little you did not ask for.

Will it slow my site down?

It is built not to. In our first measurement on a test site, loading 200 rules and checking a request took about one millisecond. That was a development setup, so we will publish numbers from a realistic server before launch.

Is AI involved?

Our plan is to use AI upstream, to help us read plugin updates and draft rules, with a person reviewing every rule. AI never runs on your visitors' requests. The checks on your site are fast, fixed rules.

What if Guardian blocks something it should not?

Rules are narrow and tested against normal traffic before release, and we can withdraw a rule everywhere within minutes. You can also add a one-line setting, or create a file, to switch Guardian off immediately.

Where will my data be?

We plan to host in the EU. The free engine sends no data about your site. We will publish exactly what the paid plans send, and why, before launch.

Guardian is a working name. Will it change?

Possibly. We still have to check the trademark.
